图 1 · 智能客服业务流程

flowchart TD 下载 SVG ↓

从用户接入到人工兜底的完整链路：意图识别 → 知识库检索（RAG） → 生成回答， 置信度或召回不足时自动创建工单转人工。菱形为判断节点，圆柱为落库节点。

flowchart TD
  U([用户发起会话]) --> C{识别接入渠道}
  C -->|App / 微信 / 电话| NLU[加载用户画像 + 意图识别]
  NLU --> CONF{置信度 ≥ 0.78 ?}
  CONF -->|否| ASK[澄清追问 / 给出候选意图]
  ASK --> NLU
  CONF -->|是| RAG[知识库语义检索 RAG]
  RAG --> HIT{召回结果达标 ?}
  HIT -->|否| T[创建工单 · 转人工坐席]
  HIT -->|是| ANS[生成回答 + 引用来源]
  ANS --> FB{用户反馈}
  FB -->|未解决| T
  FB -->|已解决| DONE([结束会话并归档])
  T --> DONE
  DONE --> DB[(会话日志入数据湖)]

  %% 样式：classDef 批量定义节点外观（浅色主题会换一套浅底配色）
  classDef judge fill:#2a2440,stroke:#a78bfa,color:#e8ecf6
  classDef human fill:#3a2030,stroke:#f472b6,color:#e8ecf6
  class CONF,HIT,FB judge
  class T human

图 1 要点

  • 首行 flowchart TD 定方向：TD 自上而下，LR 左右布局
  • 节点形状写在括号里：[矩形]、{菱形}、([圆角])、[(圆柱)]
  • 连线文字用 -->|文字|，箭头方向由 --> / --- 决定
  • classDef 定义样式类，class 批量套用，比逐节点 style 更易维护
  • 节点 ID 用英文短名（NLU / RAG），显示文字写在括号里，便于后续改文案

图 2 要点

  • erDiagram 先写关系行，再写实体字段块，顺序可任意
  • 基数符号：|| 恰好一个、o| 零或一个、o{ 零或多
  • 字段格式为 类型 名称 键 "注释"，PK / FK 会加下划线标记
  • 类型必须是单个单词（varchar、bigint），不能写 varchar(64)
  • 中文说明必须用双引号包裹，否则解析报错
